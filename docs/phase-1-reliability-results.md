## Boundaries and deferred recovery

- ProcessHandle descendant termination is best effort, not an OS process-group sandbox. Windows/non-POSIX portability was not validated; temporary permissions target the current macOS/Linux deployment model. Deadlines apply per subprocess, not one aggregate render-job deadline.
- File cleanup cannot guarantee success after process crashes, storage/permission failure, or an unresponsive kernel. Cleanup failures are logged or retained as suppressed failures. Import compensation failure deliberately retains media for reconciliation rather than destroying referenced files.
- JsonDB field conditions and existing process-local callback locks do **not** provide a transaction across HTTP, files, Telegram, multiple processes, or independent database instances. Publication send/weight/history updates and deletion/media consistency still need the later recovery architecture. No durable notification retry/outbox was added.
- ZIP extraction tests are not a coherent live snapshot/whole-application restore drill. Mutations during backups are not frozen. Database/media snapshot consistency and independent restoration remain Phase 5 work.
- HTTP authentication/authorization redesign, CSRF, ProblemDetail mapping, actor auditing and report DTO exposure remain Phase 2. Existing callback actor/binding protection is preserved; no new HTTP security guarantees are claimed.
- No unresolved blocker remains for the scoped Phase 1 acceptance items. Main-agent review and Phases 2–5 are still required before broader production-readiness claims.
