## Product rule: one selected source, two representations

The supplied examples require the selected source's **image and description to stay paired**. Model a source slot independently of an area's kind. An image area bound to Source 1 and a text area bound to Source 1 consume **one** selected source, not two random draws.

Examples:

- Three photo areas bound to slots 1/2/3, with three corresponding text areas containing `Candidato {{source.description}}` or just `{{source.description}}`.
- A profile image and a text box both bound to slot 1, with `{{source.description}} entrou no grupo`.
- Static template text, without any placeholder, stays unchanged when example descriptions change.

`Source.description` already participates in metadata, normalized name uniqueness, filtering and selection; the missing feature is **rendering it into memes**. The spike never reads or modifies actual sources.

**Text-only templates are explicitly approved.** A base template bitmap can contain 1–128 text areas and no image areas. A dynamic box may use Source 1 without any paired photo box; several boxes referencing it still select that source once. An all-literal template uses `sourceSlot: null` and zero selected sources (`K = 0`). Keep an empty source list distinct from legacy null history; no dummy image area/source, random-pool requirement or source-weight decrement is introduced. Normal template moderation/publication/template-weight/history still apply. Include both text-only variants in the native PoC and phase-2 repository/render/publication/restore tests, with no backend-preview gate. Later local K=0 preview has no samples.

## Implemented version-1 definition foundation

`application/creator/TemplateDefinition`, `TemplateDefinitionCodec` and `TemplateDefinitionValidator` implement a pure contract, not HTTP intake, persistence or rendering:

- Version **1**, `ORIGINAL_IMAGE_PIXELS`, ordered immutable area lists with unique UUIDs and sealed `ImageArea`/`TextArea` records; 1–128 areas. Image quads copy values into a local temporary quad to reuse `MediaValidation.geometry`; no legacy entity or geometry behavior changes.
- A strict manual Jackson 2 codec bounds JSON to **256 KiB**, depth **16**, numeric length **64**, rejecting unknown/duplicate fields, trailing tokens and wrong types. `boxFill` alone is optional; missing or null means no fill. Encoding has explicit deterministic field order for round-trips, **not a frozen canonical idempotency fingerprint**.
- Image/text slot union must be contiguous `1..K`; repeated references count once. Dynamic text requires a non-null slot; literal-only text **must** use null. Text-only and all-literal **K=0** definitions are valid. Validation returns K only: source-pool admission/selection, weights and publication/history behavior are not implemented by it.
- Canvas limits remain **40MP / 10,000 per side**; coordinates stay within ±10,000 with positive-area overlap, including valid off-canvas areas. Optional decoded dimensions must match the declared canvas.
- Initial/provisional validation bounds: pattern **4,096 UTF-16 units**, text box **2MP / 2,048 per side**, font size **1..128**, outline **0..4**, padding **0..64**, line height **1..2**. These are input bounds, not native capacity, fitting, expanded-description or full-glyph proof. NFD and explicit newlines are preserved without normalization.
- `catalog-v1` allows `liberation-sans`, `liberation-serif`, `liberation-mono`, weights 400/700; these are named contract allowlists, not bundled font artifacts or published capabilities. Only `SHRINK_TO_FIT` is accepted; actual fitting/rendering remains integration work.

`TemplateDefinitionTest`, `TemplateDefinitionCodecTest` and `TemplateDefinitionValidatorTest`, focused Gradle verification and the full Java suite passed with explicit Corretto 21.0.7; this is below the maintenance floor, not CI/release or native-rendering parity. No stored `Template.areas`, schema/repository, upload/submit/capabilities/receipt endpoint or production-text integration change follows from these tests. Authentication/session implementation and its separate evidence boundary are in [maintenance](../maintenance.md#creator-foundations-implemented-remaining-contracts-planned).

## Text contract and remaining integration

Keep a typed `image`/`text` area distinction and a library-independent document. A text area has:

| Field | Semantics |
| --- | --- |
| Source binding | Dynamic-text slot within this generation, independent of image areas; same slot if paired with an image. Null for literal-only text. |
| Rectangle | Original-image x/y/width/height; axis-aligned initially |
| Text pattern | Static text and optional `{{source.description}}` tokens |
| Font ID / weight | Curated font catalog and normal/bold, not an arbitrary path/URL/CSS string |
| Size / fitting floor | Font size in original-image pixels; automatic shrink with a bounded positive engineering floor, independent of editor zoom |
| Color / outline | Validated colors and bounded outline width |
| Optional box fill | Solid color behind the glyphs, useful for covering an existing caption; separate from the behind-template plane |
| Alignment / line-height | Left/center/right and bounded spacing |
| Overflow | Automatic shrink-to-fit; no clipping, ellipsis or dropped characters |
| Plane / order | Behind template or in front; images and texts share order within each plane |

The spike uses browser font aliases `sans`, `serif`, `mono`; this is **not** the production font catalog. Rectangle text is sufficient for both supplied examples. Rotation, perspective text, rich text, multiple source placeholders inside one box, automatic case changes and free-form expressions are deferred rather than hidden assumptions. A four-corner image and a rectangular text box can still share one editor scene.

### Plain-text substitution, not a scripting language

The implemented validator accepts only the exact token `{{source.description}}`, with no internal whitespace or aliases; surrounding literal text/whitespace is preserved. Unknown/malformed double-brace tokens are rejected; single braces are literal. No HTML, JavaScript, SpEL, Handlebars helpers, arbitrary object access or recursive evaluation. Renderer integration must insert a description literally in one pass: `<b>Nome</b>`, `{{unexpected}}`, percent sequences and backslashes in the description are **content**, not new instructions; validation alone does not implement substitution.

The local model bounds pattern and sample description to 512 UTF-16 units, expanded text to 16,384 and JSON to 128 KiB. These are **spike** limits, not an existing database guarantee. Set measured production work limits without changing description normalization or silently truncating metadata. The user confirms descriptions are mandatory in normal source intake: no missing-description UX/fallback decision is needed. Existing nullable/imported malformed data remains defensively validated; a selected invalid description fails explicitly rather than printing “null” or rerolling. This does not change historical nullable persistence contracts.

Resolve against the source selection already made for the generation. Required slots are the distinct union of **image and text bindings**, including text-only usage. For a nonempty union, select each slot once with the existing approved-source/history-capacity policy. For all-literal `K = 0`, bypass source selection/capacity/weight work and render with an empty selected-source list; zero image areas is not an error in the typed format. A reused slot is never reselected for its text. Reject missing/noncontiguous dynamic bindings before external work.

### Wrapping and fitting

Define authoritative backend layout rules below. The initial Konva preview approximates them locally; exact browser/native wrapping, metrics or pixel parity is not mandatory. Revisit preview alternatives if visible mismatch becomes evident:

1. Substitute literal descriptions first; preserve explicit line breaks.
2. Wrap words within the box after padding/outline allowance; split oversized words only at grapheme boundaries (accents/surrogate pairs/ZWJ emoji must not be cut apart).
3. Automatically choose the largest bounded positive size ≤ requested size that fits width and height. Proposed engineering floor is 1 original-image pixel; it is not an agreed production readability cutoff. Fitting iterations are bounded and measured in the PoC, not an unbounded loop.
4. Never clip, ellipsize, drop characters or grow the template. Invalid/physically impossible boxes still need an actionable typed failure if nothing fits at the positive floor; “shrink” cannot guarantee arbitrary text fits any tiny box. Warn visibly about very small fitted sizes without adding a new clipping product option.

The historical spike shows resolved text, fitted size, line count and overflow state; its older clipping options are not the selected production policy. Store pattern/style, not a sample's fitted result. Magick backend generation must repeat fitting for every real description; a synthetic short local sample does not prove later names fit. Reject impossible/over-budget work explicitly, never silently clip or reroll publication. The gallery's illustrative 12px warning is not a production threshold. The native PoC now measures explicit descending integer sizes, not Magick auto-fit suggestions or a numeric binary-search monotonicity assumption. That correction is implemented only in the harness; preserved bytes, measured dimensions or final-box margins still do not establish complete native glyph/grapheme coverage.

MVP language is **pt-BR**, including accented Latin text. A few common plain font families are selected below; complex scripts/bidi/color emoji are not promised. Glyph/decode tests remain necessary even though missing descriptions are not a normal product case; browser display is not VPS proof.

## Fonts and native rendering: implementation regressions and enablement

Selected plain families: **Liberation Sans, Liberation Serif and Liberation Mono**, regular/bold (400/700), with Sans as default. [Upstream](https://github.com/liberationfonts/liberation-fonts) targets Arial/Times New Roman/Courier New metric compatibility; its [license](https://github.com/liberationfonts/liberation-fonts/blob/main/LICENSE) is OFL-1.1. The native harness prepares hash-pinned 2.1.5 faces/LICENSE in private temporary storage and checks sampled pt-BR glyphs. This is not a global font installation, shipped browser/server catalog or complete glyph/legal acceptance. Retain verified artifacts/notices before packaging; no proprietary OS aliases, uploaded/remote font URLs or silent unknown-ID fallback. Await browser font loading before measurement.

**Selected implementation direction: Magick literal text and existing image composition, accepted for development.** Do not run more PoC/gallery comparisons or require a full Unicode audit before implementation. The historical **Java 21 headless Java2D/TextLayout raster → Magick compositor** remains comparison evidence, not an active production strategy. A literal rasterizer boundary separates text/layout from perspective distortion with typed ownership/cleanup; text shares the behind-template/template/foreground stack. Carry normal pt-BR glyph/layout/style issues into implementation regression tests and retain a small isolated Linux sandbox smoke before production enablement. No Node/Skia/headless-browser/Java2D migration, cap increase or readiness claim follows.

Argument-array ProcessBuilder calls prevent shell interpolation but do **not** make ImageMagick's text grammar literal: [percent/property escapes](https://imagemagick.org/escape/) include `%[...]` and `fx:` expression expansion. Do not directly feed untrusted descriptions into `label:`, `caption:`, `-annotate`, MVG/Pango/HTML or file-indirection-capable text operands and assume quoting solves it. The local owned-file metacharacter fixtures passed their finite matrix; production integration must preserve/prove literal semantics and resource bounds, not generalize that into a full sandbox audit.

Server-owned paths, bounded raster dimensions/pixels/text/layout iterations, font IDs/colors and render admission must be validated before expensive work. The documented host has a 256m maximum heap and **448M service ceiling shared with native children / 64M swap ceiling**; a 40MP RGBA buffer alone is about 160MB. Preserve native memory/map/disk/thread/time caps and use bounded box-sized rasters and aggregate work/deadline/admission budgets, not a full template buffer per text box or a raised memory ceiling. The local 40MP native baseline exhausted its pixel cache before text; completed 128-box fixtures do not prove aggregate service capacity. Linux extracted AppRun under actual NoNewPrivileges/private-temp/filesystem hardening and heap64m/256m still need evidence. Preserve image distortion, masks, alpha, interruption, owner-only scratch and final-artifact ownership. No network/font loading in a render transaction; selection, rasterization and Telegram/filesystem effects are not database transactions.

Backend rendering fixtures must exercise fixed long/short/multiline/accented descriptions, glyph handling, outline extents, alpha and both planes under the real sandbox; they do not require a server-preview API. All harness captions now explicitly use `-stroke none` for zero outline; production is unchanged. Shared `spikes/native-text/MagickCaptionFitter.java`, covered by pure tests and included in runner compilation/source hashes, serves main and visual callers. It measures free-height `caption:split=true` at descending explicit sizes 1..128, checks every larger integer before accepting within budget, batches at most eight probes per process with a dummy 1×1 image and deletion of each raster, then strictly verifies rerendered dimensions. Native fitting admission no longer uses Java2D fit; Java retains font glyph checks and model/oracle comparison.

**Before correction:** the isolated long-word split probe improved auto-fit from 1px to 12px (224×75 output within 224×94); NFD still suggested 7px despite an explicit 28px fit, and NFC's suggested 31px exceeded the height before verification selected 30px. These remain historical evidence, not unresolved helper behavior. Corrected local NFD/NFC fixtures fit at 30px and the long word at 13px with original UTF-8 hashes unchanged; counter caps and largest-measured-integer checks passed. No normalization is selected. See the [PoC bounds](backend-architecture.md#4-rendering-proof-of-concept-before-backend-implementation): at most 128 probes, 17 fit commands and 16,000,000 scalar work units counting probes plus rerender, with input/box caps and unchanged deadlines. This heuristic is neither memory/latency proof nor a production contract. The heavy shrink fixture now retains FAIL with explicit `FIT_WORK_LIMIT`, not deadline exhaustion; do not silently lower the positive floor or extend timeouts.

Local Python/pure fitter/self-test/smoke success and completed 128-area candidates are not production safety proof. Native FAIL/LIMITATION and Java comparison LIMITATION remain visible; no execution success or preserved bytes establishes complete glyph coverage. Caption clipping, multiline/line-height, alignment and style cases now belong to renderer implementation regressions, not another phase-1 research round. Keep `FIT_WORK_LIMIT` and the 40MP capacity rejection explicit, never relabel them as passes or raise caps to hide them. Production enablement still requires the small isolated Linux smoke under actual hardening.

Initial [Preview is client-only Konva](backend-architecture.md#5-client-only-preview-and-deferred-alternatives), optionally using client-generated synthetic examples; no files are uploaded and no native-preview call occurs. ## Persistence and compatibility work, deliberately not done here

Current `TemplateArea`/CSV and `ImageRenderer.Request` represent image quadrilaterals only. Do not bolt text properties onto CSV rows, infer text from magic source IDs, or silently export only image areas. The spike imports/exports the existing CSV only for image-only documents and refuses CSV export when any text exists. Mixed documents use clearly experimental typed JSON; the bot cannot accept it. The local image is not embedded in that JSON.

Build on the implemented version-1 closed definition/codec/validator above; HTTP media intake and stored legacy/CSV translation remain pending. Next implement durable submission, explicit verified origin/confirmation/notification routing and actor/key receipts in **SQLite only**, with new schema migrations, versioned offline JSON bundle export/import/backup/restore and data-aware rollback; then integrate source selection and Magick generation/workflow using the new types, **before** either frontend milestone. JSON bundles are not the JsonDB engine: preserve existing legacy JsonDB/JSON round-trips/import/export/recovery, but never route new mixed data or receipts through JsonDB. Future unsupported creator persistence there must fail closed clearly; no such runtime/CLI rejection is implemented by this plan. JsonDB runtime/default retirement is separate later scope, with legacy adapters/tests retained now. The initial frontend uses only the image subset. Preserve legacy coordinates/data rather than projecting mixed text into CSV or `Template.areas`. Exact new SQLite schema remains proposed; schema/binary compatibility needs migration tests and operator approval, and no data cutover is authorized here.

Unknown template versions must fail clearly rather than drop text or overwrite old definitions. Retain original media/metadata during conversions. Test mixed templates through functional restore and post-write export before enabling them; existing image templates must still generate exactly as before.
