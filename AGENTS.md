## Source boundaries

- Base package: `com.boatarde.regatasimulator`; main/test code lives under `src/main/java` and `src/test/java`.
- Configuration: `src/main/resources/application*.yml`; legacy browser source: `src/main/resources/static/`; new editor/build source: `frontend/template-creator/`. Never hand-edit generated editor assets.
- Never edit generated `build/` resources/classes/reports or `.gradle/` caches. Stale build contents are not authoritative source.
- CI lives in `.github/workflows/`; checked-in deployment/unit/launcher replace the historical generated `subprocess` wrapper. Approved releases update the shared unit and JAR with captured-unit/artifact fallback. Linux bootstrap, host drop-ins, private env/root/Java/SSH trust remain operator-provisioned.

## Build and validation

- Use Java 21 and checked-in Gradle **8.14.6** with distribution SHA-256 validation. CI targets checksum-verified Temurin **21.0.12.1+1**; `verifyMaintenanceJava` rejects older Java 21 for release/CI. See maintenance for exact-JDK installation/toolchain proof; do not install globally as routine verification.
- Runtime versions/locks are authoritative in `build.gradle`, `gradle.lockfile` and wrapper/workflows. See maintenance for compatible Spring/Jackson families; keep dependency/schema changes separately scoped and tested.
- `./gradlew test` for normal verification; `./gradlew clean test` for a clean baseline; `./gradlew clean build` for clean Java verification/editor packaging; `./gradlew bootJar` for the executable JAR. These alone do not establish full CI/release parity; keep maintenance-Java, frontend/browser/package and security gates separate.
- Target tests with `./gradlew test --tests 'fully.qualified.TestClass'`.
- Node checks: `node --test src/test/js/*.test.cjs` (web-security/deployment/scanner, separate from Gradle and included in CI); use `node --check` for edited browser JS. `./gradlew dependencyScan` fails on findings/incomplete results; Maven-only, not native/JDK/CDN coverage or legal clearance. Do not freeze test/scan counts in docs as timeless guarantees.
- Editor install: `npm ci --ignore-scripts --include=dev --include=optional --prefix frontend/template-creator`; preserve optional platform esbuild binaries with lifecycle scripts disabled. `./gradlew frontendCheck` runs syntax/model/media/Telegram checks, not browser/audit/package gates. See maintenance for the separate prefixed npm commands. `npm start --prefix frontend/template-creator` rebuilds and serves only `127.0.0.1:4174/create/editor/`, without Spring/bot startup; use generated fixtures, never `spikes/example/` or user images as test inputs.
- Focused Telegram checks: `node --check frontend/template-creator/telegram.mjs` and `node --test frontend/template-creator/test/telegram.test.mjs`; these are also covered by the npm syntax/unit gates and CI `frontendCheck`. After every delivered editor slice refresh `npm start --prefix frontend/template-creator -- --lan` and provide newly printed reachable phone URLs on trusted Wi-Fi; default/CI remains loopback-only. LAN preview is not hardware/Telegram acceptance or release permission; documentation-only changes launch no server.

## Runtime and data safety

- Do not start `bootRun`, register bots, publish memes, send backups, or deploy as routine verification. Startup invokes Telegram and schedules side effects. Use isolated test adapters/storage; explicitly requested live tests need a dedicated development bot/environment.
- Bot registration and schedules default on. Tests must disable `telegram.bots.regata-simulator.registration-enabled` and `regata-simulator.scheduling.enabled` **and** mock external calls; these switches do not disable manual mutations or Telegram health checks.
- Never read/write/delete production data to test a migration or cleanup. Copy data to isolated storage, back it up, validate import/restore, and document rollback first.
- Required runtime variables: `REGATA_SIMULATOR_ENC_PASSWORD`, `REGATA_SIMULATOR_DB_PATH`, `REGATA_SIMULATOR_SOURCES_PATH`, `REGATA_SIMULATOR_TEMPLATES_PATH`, `MAGICK_PATH`; select profile with `SPRING_PROFILES_ACTIVE`.
- `.env`/`.env.dev` are not automatically loaded by Spring Boot. Ensure local environment files are Git-ignored before entering real secrets. Do not print decrypted configuration, tokens, passwords, or token-bearing Telegram URLs.
- JsonDB collections are `sources`, `templates`, `memes`, `users`, and `audits`. Storage initializes before bot registration. Images live in separate UUID directories. Imported sources may have no Telegram Message; preserve that nullable contract.
- Do not assume database transactions cover filesystem or Telegram effects. Explicitly handle partial failure, cleanup, and recovery.
- JsonDB remains the compatibility default; production explicitly selects SQLite with `regata-simulator.database.engine=sqlite` and absolute `sqlite-file`. Never reinterpret/import legacy storage on startup. Retain the WAL-reset guard, per-connection FK/FULL/busy settings and small pool/local-disk single-host constraints.
- Offline `offlineStore`, `restoreBundle` and `inspectRecoveryStages` never start Spring. Use coherent stopped **isolated copies**, canonical absolute paths, new nonoverlapping outputs and explicit acknowledgment; exact contracts are in the operations runbook. Preserve manifests/anomalies. Post-write rollback exports new SQLite writes/media/audits into new JSON bundles; never point an old binary at stale JSON.
- Configured backups capture WAL-aware `VACUUM INTO`/JsonDB metadata plus copied media under a cooperative single-JVM barrier, then package/deliver outside it. Require an existing private nonoverlapping `regata-simulator.backup.local-directory`; count retention defaults to 7. Manual reconciliation, independent recovery storage and functional restore checks remain operator responsibilities.
- The native Jasypt 1.9.3 PBE bridge preserves legacy `ENC(...)` with 1,000 iterations/random salt/IV, not a recommended new KDF. The flagged starter/GCM dependency is removed, not suppressed. Preserve cause-free `EncryptedPropertyFailure extends Error` (Boot opaque-source fallback prevention), `MapPropertySource` type/original map, precedence and lazy reads; test with synthetic ciphertext only.

## Change conventions

- Preserve four-space Java formatting, existing package layout, Lombok usage, and constructor injection; avoid unrelated reformatting.
- Keep public API paths/body shapes, Telegram callback format, template CSV format, and Portuguese messages compatible unless changing them is intentional and documented.
- Prefer typed use-case inputs/results, thin adapters, domain services, and reusable rendering/storage/Telegram boundaries for new work. Do not grow the custom workflow framework unnecessarily or rewrite it as a side effect of an unrelated task.
- Production Telegram dispatch uses `TelegramRouter` and typed services; HTTP/scheduler adapters share services and JsonDB/SQLite repository contracts. Obsolete runner/step/route classes and duplicate regression harnesses are removed; do not restore them or add workflows. `ReviewCallbackStepsTest` tests active adapters despite its name/package. Services are synchronous, not durable/resumable infrastructure.
- Separate submitter confirmation from administrator approval. Check actor authorization and allowed status transitions for callback and HTTP mutations.
- SQLite history stores immutable UUIDs/positions plus nullable FK links, preserving duplicates/orphans/order across current-item deletion. NFKC/ROOT source-name UNIQUE conflicts fail explicitly; nullable legacy names/origins remain. Geometry/full nullable Messages are validated JSON. Keep metadata-only unit-of-work transactions around publication weights/history and author/submission inserts, never network or media.
- Media deletion stages `.delete-<item UUID>-<operation UUID>` beside original storage, then removes metadata and purges. Confirmed metadata failure restores; uncertain DB/restore/purge failures retain staged bytes. Do not automatically purge stages or overwrite restored directories: freeze writers, inspect coherent copies and reconcile as documented. This is compensation, not a crash-proof distributed transaction.
- Preview callbacks require the original submitter, REVIEW status, and stored preview chat/message binding. Legacy/unbound items fail closed; never trust callback metadata to backfill ownership. Preserve the original upload Message, and update binding fields without saving stale full-entity snapshots. Same-item callback locks are process-local, not a cross-adapter/database transaction.
- Keep per-job scratch files isolated. Bound external process/network work, check exit codes, preserve interruption, and clean up on failure. Retain argument-array ProcessBuilder calls rather than shell interpolation.
- Rendering transfers owner-only scratch ownership via `RenderedImage` to `MemeService` through delivery/persistence; never move scratch back into template directories or delete the final artifact before sending. Process pipe readers use platform threads to avoid Java 21 pinning. Current permissions target macOS/Linux; do not claim untested Windows portability.
- Photo retries are send-only: at most three calls/10 seconds waiting, same artifact, definite connect failures or bounded explicit 429 only. Never retry whole publication, ambiguous delivery or post-send metadata failures; preserve interruption and single metadata commit. Shared IPv4 flags belong in the release launcher; host Java/heap/resource settings stay in preserved drop-ins, not full ExecStart overrides.
- ImageMagick AppImage FUSE mounts fail under NoNewPrivileges. Keep sandboxing; use the privately extracted `squashfs-root/AppRun` native launcher and test complete renders under actual service hardening/environment, not only heap/cgroup limits or SSH.
- Preserve capacity-aware history exclusion, birthday fallback, explicit `application.ApplicationFailure` outcomes, strict Telegram dispatch and typed preview/publication modes. The obsolete workflow enum/bag/registration/transition machinery is removed.
- Use valid generated ImageIO fixtures for successful upload/import tests. Validate byte/pixel bounds, CSV headers/limits, ordered contiguous indices/slots and convex corners bounded to ±10,000. Intentional off-canvas corners are supported unchanged; each area must have positive-area intersection with the decoded image (edge/corner-only touching is rejected). Rendering uses the same overlap rule. Import reports include every row outcome; normalization uses NFKC/Locale.ROOT. Compensate metadata before deleting referenced import media and retain uncertain failures for reconciliation.
- The image-only editor keeps pure original-pixel geometry separate from Konva/view state; rectangle corner/paired-edge constraints and independent perspective corners, anchored ghost/apply/cancel and undo must preserve fixed points. Its 11-column CSV importer accepts contiguous Area indices starting at 0 or 1 and exports normalized 1-based indices; backend acceptance remains 1-based only. Preserve imported repeated source slots even outside the adjacency picker's choices and valid off-canvas overlap. Local PNG/JPEG limits are 20 MiB/40MP/10,000 per side, with a 1 MiB predecode header bound. PNG additionally walks at most 2,048 chunk headers/1 MiB of inspected metadata, skipping compressed payloads, to check EXIF even after IDAT; non-1 orientation is refused with normalize-a-copy guidance. Require full `createImageBitmap` decode, dimension checks, bitmap closure (including late completion) and a shared 15-second image/bitmap timeout, failing closed without API support. This is not a hard decoder memory/cancellation guarantee or full device/release parity.
- REVIEW-only moderation writes status/binding fields, not stale entity snapshots. Applied decisions survive notification failure; HTTP 204 may carry `X-Notification-Status: failed`. Null-origin items skip notifications. Repeated/lost REVIEW transitions are typed conflicts (HTTP 409); this does not add durable retries.
- Backup items/encoded archives above 40 MiB fail explicitly. Retain complete local bundles after delivery failure; validate manifest/parts and fresh-target `RESTORED_VERIFIED`. Limits/cleanup/retention and stage-inspection policies are in the operations runbook. No exactly-once delivery, crash-proof recovery or whole-host restore is claimed.
- Treat CORS origins/cookie domains as deployable public configuration, not secrets. CORS is not authentication or CSRF protection; test security changes through the full filter chain.
- Web security uses validated `regata-simulator.web` properties and one CORS source: deny cross-origin by default, exact lists only. One CookieSerializer defaults host-only/Secure/HttpOnly/Lax; dev explicitly opts out of Secure, stage/prod cannot. Preserve Telegram frame ancestors; test authenticated iframe/WebView requirements explicitly.
- HTTP APIs require ROLE_ADMIN except public login/CSRF token acquisition; local liveness/readiness probes are anonymous and never call Telegram. CSRF uses Security 7.1 session/XOR tokens; `/api/csrf` is no-store. Unsafe clients refresh after login/logout and never auto-replay mutations. Admin publish/backup are POST-only. API auth failures are generic 401/403; login throttling is bounded/process-local.
- Preserve low-cardinality redacted operation telemetry and actor/time audits. SQLite REVIEW transition/audit is atomic; JsonDB decision/audit writes are not. Local probes are not external/storage/render readiness; bounded external Telegram health remains protected. Schedules have configurable cron/zone and graceful shutdown, not durable jobs.
- Validate HTTP pagination/body inputs and use generic ProblemDetail errors (400/404/409/503/500). Return gallery/import DTOs, not persisted Telegram Message/preview bindings. Preserve minimal `message.from` name compatibility and byte-detected PNG/JPEG MIME on legacy `.png` URLs; `/import/report` exposes safe ordered row outcomes.
- Introduce SQLite, schema migrations, and dependency upgrades only in explicitly scoped changes with data migration/backup tests. Do not assume review proposals are already present.
- Update `docs/` and this guidance when architecture, setup, or verified commands change. Report what was tested and any real verification limits.
